# TeachHelper: мобильный редизайн

## Что реализовано

Интерактивный React-интерфейс на основе возможностей mifnail/tech: экран «Сегодня», недельное расписание и календарь, группы, предметы, журнал оценок и посещаемости, отчёты, профиль. На смартфонах — нижняя навигация и компактный журнал. SVG-иконки и системный шрифт не требуют внешних загрузок. Нет фоновых изображений, анимационных библиотек или редактора таблиц.

Оценки, занятия, группы и профиль сохраняются в localStorage с префиксом `teachhelper-demo-`. Экспорт формирует настоящий XLSX (OOXML в ZIP) с сохранёнными оценками. В именах скачиваемых файлов используется транслитерация для совместимости браузеров.

## Важные ограничения

Это самостоятельная демонстрационная реализация фронтенда, а не готовый APK или внесённый в GitHub патч. Исходный Flask backend, lessons.db и Android-проект отсутствуют в рабочем окружении. SQLite-схема, миграции и рабочие данные не изменялись.

Демонстрационная дата: 14 сентября 2026. Начальные группы, студенты, аналитические показатели и уведомления — примеры, а не данные пользователя. Новая группа создаётся пустой. Управление реальными списками студентов, ботами, SQLite-бэкапами и нативным Android-шарингом требует подключения оригинального backend.

Нельзя восстанавливать JSON-копию демоданных вместо SQLite-файла lessons.db.

## Структура

- `src/App.tsx` — маршруты интерфейса, формы, журнал и состояние представления.
- `src/data.ts` — типы представления, демоданные и изолированное локальное хранение.
- `src/components/Icon.tsx` — небольшой набор SVG-иконок.
- `src/export.ts` — экспорт XLSX и скачивание.
- `src/index.css` — адаптивные стили.
- `tests/smoke.mjs` — браузерная проверка.

## Интеграция без изменения базы

Изучен исходный `api.py` репозитория. При переносе интерфейса используйте существующие контракты, не создавая новых таблиц и не записывая демоданные в SQLite:

- `GET /api/groups`, `POST /api/groups` с `{name}`.
- `GET /api/students?group_id=...`.
- `GET /api/subjects?group_id=...`.
- `GET /api/schedule/today`, `GET /api/schedule`.
- `POST /api/lessons` с `subject_id`, `date`, `lesson_number`.
- `GET /api/lessons/:id/attendance`.
- `POST /api/lessons/:id/attendance` с `{student_id, grade}` либо массивом таких объектов.
- `GET /api/export/grades/:subject_id.xlsx`.
- `POST /api/export/grades/:subject_id/share` — оригинальный Android-путь.
- `POST /api/backup` — оригинальная SQLite-копия.

Поля представления (кабинет, время, названия групп) не являются новой схемой БД. Их нужно получать из существующего расписания и справочников через адаптер. Значения UI, в частности «—» и «Н», перед записью необходимо преобразовать в исходное представление оценок/посещаемости из database.py; не отправлять UI-строки в API без проверки контракта. Demo-ID студентов сейчас отсутствуют — при интеграции необходимо использовать реальные `student_id`, а не ФИО.

## Android 7+

Проверена адаптивная вёрстка в современном Chromium на ширине 360 px. Проверка на физическом Android 7, сборка APK и проверка старого System WebView не выполнялись. Версия ОС не определяет версию WebView. Текущая Vite/React-сборка использует ES-модули и требует современного WebView; поддержку штатного WebView Android 7 заявлять нельзя.

Для production APK следует переносить представления в существующий vanilla-JS frontend либо отдельно настроить legacy-сборку, полифиллы и CSS-fallbacks под минимальную версию WebView. Исходный стек репозитория не требуется заменять React-стеком этой демонстрации. Обязательны регрессионные тесты исходного Python-проекта, проверка обновления APK без потери данных, сохранения/шаринга файлов, клавиатуры, safe areas и поведения без сети.

## Проверки

- `npx tsc --noEmit`
- `npm run build`
- `npm run dev -- --host 0.0.0.0`, затем `node tests/smoke.mjs`

Браузерный тест проверяет отсутствие runtime-ошибок и горизонтального переполнения на 360 px, сохранение оценки после перезагрузки, создание группы, скачивание XLSX и фильтрацию по дню. Для запуска нужны Chromium и системные зависимости Playwright.
