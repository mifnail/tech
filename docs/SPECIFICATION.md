# Спецификация системы «Учёт занятий» (TeachHelper4)

## 1. Назначение системы
Мобильное (Android APK) и десктопное кроссплатформенное приложение для преподавателя колледжа/вуза, предназначенное для:
- Ведения электронного журнала проведённых занятий
- Учёта посещаемости и успеваемости студентов
- Контроля выполнения учебного плана (плановые vs фактические часы)
- Оперативного учёта замен предметов и отмен занятий
- Формирования и экспорта отчётов (PDF, Excel, iCalendar) с поддержкой системного обмена файлами (Share Sheet)

## 3. Модель данных и Схема БД

### 3.1 ER-диаграмма связей

```
┌──────────────┐       ┌─────────────────┐
│   groups     │       │    subjects     │
├──────────────┤       ├─────────────────┤
│ id (PK)      │──┐    │ id (PK)         │──┐
│ name (UNIQUE)│  │    │ name            │  │
└──────────────┘  │    │ total_hours     │  │
                  │    │ group_id (FK)   │←─┘  (ON DELETE CASCADE)
                  │    └────────┬────────┘
                  │             │
                  │    ┌────────┴────────┐
                  │    │   schedule      │
                  │    ├─────────────────┤
                  │    │ id (PK)         │
                  │    │ day_of_week     │
                  │    │ lesson_number   │
                  │    │ subject_id (FK) │── FK → subjects.id (ON DELETE CASCADE)
                  │    │ week_type       │  (0=каждая, 1=нечёт, 2=чёт)
                  │    └─────────────────┘
                  │
┌──────────────┐  │    ┌─────────────────┐
│   students   │  │    │    lessons      │
├──────────────┤  │    ├─────────────────┤
│ id (PK)      │  │    │ id (PK)         │
│ group_id (FK)│←─┘    │ subject_id (FK) │── FK → subjects.id (плановый)
│ last_name    │       │ actual_subj (FK)│── FK → subjects.id (фактический)
│ first_name   │       │ date            │  (формат YYYY-MM-DD)
│ middle_name  │       │ status          │  ('held' | 'cancelled' | 'free')
└──────────────┘       └────────┬────────┘
     │                          │
     │    ┌─────────────────┐   │
     │    │    grades       │   │
     │    ├─────────────────┤   │
     └───→│ id (PK)         │   │
          │ lesson_id (FK)  │←──┘  (ON DELETE CASCADE)
          │ student_id (FK) │── FK → students.id (ON DELETE CASCADE)
          │ grade           │  ('0','2','3','4','5','absent')
          └─────────────────┘
```

### 3.2 Таблицы и каскадное удаление
- `groups`: учебные группы. При удалении группы каскадно удаляются все её студенты и предметы.
- `students`: студенты группы. При удалении студента каскадно удаляются его оценки из таблицы `grades`.
- `subjects`: предметы. При удалении предмета каскадно удаляются связанные записи в `schedule`, `lessons` и `grades`.
- `schedule`: шаблон недельного расписания.
- `lessons`: фактически проведенные или созданные вручную занятия. Поддерживается создание нескольких занятий по одному предмету в день (дубликаты).
- `grades`: оценки и посещаемость студентов за конкретное занятие.

### 3.3 Статусы занятий и оценок
- **Статусы занятий:**
  - `held` — проведено (учитывается в выполненных часах).
  - `cancelled` — отменено (оценки удаляются, в выполненных часах не учитывается).
  - `free` — окно/свободно (для замен).
- **Оценки (`grades`):**
  - `0` / `present` — присутствовал без оценки (зелёный цвет).
  - `5`, `4`, `3`, `2` — успеваемость (акцентная подцветка).
  - `absent` — отсутствовал / Н/Я (красный индикатор).
  - `null` — не отмечен.

## 4. Спецификация REST API

### 4.1 Группы (`/api/groups`)
- `GET /api/groups` — список всех групп
- `POST /api/groups` — создать группу (`{"name": "..."}`)
- `PATCH /api/groups/<id>` — переименовать группу (`{"name": "..."}`)
- `DELETE /api/groups/<id>` — каскадное удаление группы

### 4.2 Студенты (`/api/students`)
- `GET /api/students?group_id=<id>` — студенты конкретной группы
- `POST /api/students/bulk` — массовое добавление студентов (`{"group_id": N, "students": [...]}`)
- `PATCH /api/students/<id>` — изменить ФИО студента (`{"last_name": "...", "first_name": "...", "middle_name": "..."}`)
- `DELETE /api/students/<id>` — каскадное удаление студента

### 4.3 Предметы (`/api/subjects`)
- `GET /api/subjects?group_id=<id>` — список предметов с расчётом прогресса (проведено/всего/осталось)
- `POST /api/subjects` — создать предмет (`{"name": "...", "total_hours": N, "group_id": N}`)
- `PATCH /api/subjects/<id>` — отредактировать предмет (`{"name": "...", "total_hours": N}`)
- `DELETE /api/subjects/<id>` — каскадное удаление предмета
- `GET /api/subjects/<id>/gradebook` — сводная ведомость оценок группы по предмету
- `GET /api/subjects/<id>/substitution-list` — список предметов для замены (включая СВОБОДНО)

### 4.4 Расписание (`/api/schedule`)
- `GET /api/schedule` — полное расписание
- `POST /api/schedule` — добавить элемент расписания
- `PATCH /api/schedule/<id>` — обновить элемент расписания
- `DELETE /api/schedule/<id>` — удалить элемент расписания
- `GET /api/schedule/today` — расписание на сегодня с учётом типа недели (чётная/нечётная) и списка проведенных занятий

### 4.5 Занятия (`/api/lessons`)
- `POST /api/lessons` — создать занятие
- `GET /api/lessons/<id>` — детали занятия (название, дата, группа, статус)
- `DELETE /api/lessons/<id>` — полное удаление занятия и его оценок
- `PATCH /api/lessons/<id>/substitute` — провести замену предмета
- `PATCH /api/lessons/<id>/cancel` — отменить занятие
- `PATCH /api/lessons/<id>/status` — изменить статус занятия
- `GET /api/lessons/<id>/attendance` — список студентов с выставленными оценками
- `POST /api/lessons/<id>/attendance` — выставление/изменение оценки студента

### 4.6 Отчёты и Экспорт (`/api/reports`, `/api/export`)
- `GET /api/reports/daily?date=YYYY-MM-DD` — дневной отчёт по занятиям
- `GET /api/reports/average/<subject_id>` — средний балл по предмету
- `GET /api/reports/substitutions` — отчёт по заменам
- `GET /api/export/report/<date>.<ext>` — экспорт отчёта за день (`.pdf`, `.xlsx`)
- `GET /api/export/grades/<subject_id>.<ext>` — экспорт ведомости (`.pdf`, `.xlsx`)
- `GET /api/export/lessons.ics` / `schedule.ics` — экспорт в формате iCalendar

## 5. Особенности UI/UX и Фронтенда

1. **Единый стандарт дат:**
   - В базе данных и API дата передаётся в ISO-формате (`YYYY-MM-DD`).
   - На клиентском интерфейсе отображение форматируется через `App.UI.formatDate` в привычный стандарт `ДД.ММ.ГГГГ`.

2. **Полный CRUD для сущностей:**
   - Для студентов, групп и предметов доступны кнопки редактирования (✎) и удаления (✕).
   - Изменение имён происходит через всплывающие модальные окна с автозаполнением.

3. **Поддержка нескольких занятий в день:**
   - Фильтрация на фронтенде работает через `lessons.filter()`, что позволяет создавать и корректно отображать произвольное количество занятий по одному предмету за день.

4. **Загрузка и Системный Share Sheet:**
   - Загрузка отчётов осуществляется асинхронно через `fetch` + `Blob` + виртуальную ссылку скачивания.
   - После успешного скачивания пользователю предлагается модальное окно с функцией **«Поделиться»** (`navigator.share`), позволяющее передать итоговый файл в мессенджеры или почтовые клиенты.

## 7. Перспективы развития (Roadmap)

Для дальнейшего расширения и масштабирования проекта рекомендуются следующие этапы:

1. **Облачная синхронизация и резервное копирование:**
   - Реализация экспорта/импорта полных дампа БД (`.db` или JSON) на Google Drive / Яндекс.Диск для защиты от потери данных при смене устройства.

2. **Импорт расписания из внешних источников:**
   - Парсинг файлов Excel / CSV / ICS от учебного отдела для автоматического заполнения структуры групп и расписания.

3. **Аналитический Дашборд:**
   - Наглядная графическая диаграмма посещаемости и успеваемости по группам.
   - Автоматическое выявление критических пропусков («группа риска» студентов).

4. **Мульти-преподавательский режим (Role-Based Access):**
   - Добавление авторизации (JWT / Сессии) для разделения журнала между несколькими преподавателями при работе с единым сервером.
