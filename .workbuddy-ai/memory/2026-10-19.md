# Пара действует с даты создания + тап ведёт в ведомость (`5d65b16`)

Запрос владельца: (1) новая пара не должна появляться на прошедших датах,
(2) тап по невыполненной паре должен открывать ведомость, а не редактор шаблона.

## valid_from

- `schedule.valid_from TEXT` — дата, с которой пара действует.
  Миграция `ALTER TABLE schedule ADD COLUMN valid_from TEXT` в `_migrate()`.
- `Database.add_schedule_entry(..., valid_from=None)` — по умолчанию
  `time.strftime('%Y-%m-%d')`. `update_schedule_entry` поле НЕ трогает.
- `api.py` POST `/api/schedule` принимает необязательный `valid_from`.
- Фронт: `ScheduleItem.validFrom`, маппинг `valid_from`, оптимистичная
  запись ставит `todayISO()`.
- `dayRows`: `if (it.validFrom && date < it.validFrom) continue;`
- `scheduleItemFor` / `scheduleItemForDay(…, date?)` тоже учитывают valid_from.
- `saveItem`: цикл `while (target < today || parity mismatch)` — после
  добавления открывается ближайшая подходящая дата, а не прошедшая.

Старые записи: `valid_from` = NULL → ограничения нет (история не меняется).

## Тап по слоту шаблона

- `openPlanRow(it)`: дата > сегодня → тост «Занятие ещё не наступило»;
  занятие в слоте уже есть → `navigate('/lesson/'+id)`; иначе
  `createLesson(groupId, subjectId, selectedISO, lessonNumber)` → переход.
- Карандаш в строке теперь и у слотов шаблона (`row.kind === "plan"`).
- `store.createLesson` пробрасывает ошибку (`throw e`), иначе вызывающий
  уходил на удалённое занятие. `NewLessonSheet` ловит и показывает тост.
